# 缠论规则规格

这份文档用于约束本项目第一阶段的缠论识别口径。目标不是覆盖所有流派，而是先确定一套可实现、可测试、可复盘的规则，作为 Python 程序的统一标准。

## 1. 范围

本版本先定义以下内容：

- K 线基础数据格式
- 预处理和包含关系处理
- 分型识别
- 笔识别
- 线段识别
- 中枢识别

本版本暂不细化以下内容：

- 趋势、盘整、背驰的完整自动识别细则
- 严格意义上的一二三类买卖点全部细则
- 多级别联立分析
- 自动交易执行

但本版本会先把严格理论口径写清楚；文档中凡明确标注为“严格口径”的定义，代表项目后续应收敛到的统一标准，不等于当前代码已经全部实现。

## 2. 统一数据约定

### 2.1 K 线字段

每根 K 线至少包含以下字段：

- `ts`: 时间戳，统一为 pandas `datetime64[ns]`
- `open`: 开盘价
- `high`: 最高价
- `low`: 最低价
- `close`: 收盘价
- `volume`: 成交量，可选但建议保留

### 2.2 顺序要求

- 数据必须按时间升序排列
- 不允许重复时间戳
- 不允许 `high < low`
- 缺失值必须在预处理阶段被剔除或修复

### 2.3 分析级别

第一阶段默认一次只分析单一级别数据，例如：

- 日线
- 30 分钟线
- 5 分钟线

不同级别不在同一次主流程中混用。

## 3. 预处理规则

### 3.1 基础清洗

进入缠论识别前，必须完成：

- 时间排序
- 重复值去重
- 无效 K 线过滤
- 必要字段类型标准化

### 3.2 包含关系处理

第一阶段采用“先去包含，再识别分型”的方案。

这里的“处理方向”仅用于包含关系合并，和后续识别出的笔方向不是同一概念。
后续某一笔被确认，不能反向决定前面某段包含关系应按向上还是向下合并。

定义相邻两根 K 线 `A`、`B`：

- 若 `A.high >= B.high` 且 `A.low <= B.low`，则 A 包含 B
- 若 `A.high <= B.high` 且 `A.low >= B.low`，则 B 包含 A

注意：

- 相等高点可以构成包含（只要低点覆盖关系成立）
- 相等低点可以构成包含（只要高点覆盖关系成立）
- 高低点同时相等也视为包含关系，可按去包含规则合并
- 只要一根 K 线的 `[low, high]` 区间完全覆盖另一根 K 线，就执行去包含合并

当出现包含关系时，使用方向相关的合并规则生成一根标准化 K 线：

- 若当前处理方向为向上，则合并后：
  - `high = max(A.high, B.high)`
  - `low = max(A.low, B.low)`
- 若当前处理方向为向下，则合并后：
  - `high = min(A.high, B.high)`
  - `low = min(A.low, B.low)`

其中“当前处理方向”定义为最近两根非包含标准化 K 线的方向：

- 若后一根的 `high` 和 `low` 都更高，方向为向上
- 若后一根的 `high` 和 `low` 都更低，方向为向下

若序列起始阶段无法判断方向，则先保留，直到出现第一个明确方向后再继续处理。

严格口径补充：

- 方向必须先确定，再执行包含合并；不能在方向未知时默认按向上或向下处理
- 一段连续包含链一旦已确定方向，在该包含链结束前应保持该方向不变
- 仅当后续出现新的“非包含标准化 K 线”组合时，才允许重新判定方向
- 不能因为“当前 bar 包含前一临时 bar”就直接把方向翻转
- 若一段包含链起始时方向未知，应先暂存该链，直到出现首个可判方向的非包含组合，再回头按该方向完成该链的合并

### 3.3 标准化 K 线输出

去包含后得到 `normalized_bars`，后续分型、笔、线段全部基于这个序列，而不是原始 K 线序列。

每根标准化 K 线需要保留：

- 合并后的 `high`、`low`
- 起止时间范围
- 对应原始 K 线索引列表

这样后续做可视化和解释时可以回溯到原始数据。

## 4. 分型定义

### 4.1 顶分型

标准化 K 线序列中，若第 `i` 根相对左右两侧都满足：

- `high[i] > high[side]`
- `low[i] > low[side]`

则第 `i` 根构成顶分型。

### 4.2 底分型

标准化 K 线序列中，若第 `i` 根相对左右两侧都满足：

- `high[i] < high[side]`
- `low[i] < low[side]`

则第 `i` 根构成底分型。

这意味着：

- “等高且低点更高”不构成严格顶分型
- “等低且高点更低”不构成严格底分型
- 例如 `03-23 / 03-24 / 03-25` 在不构成包含时，`03-24` 不再被视为严格底分型

### 4.3 分型最小窗口

- 分型必须基于连续 3 根标准化 K 线判断
- 首尾两根不能构成分型

### 4.4 分型去重规则

若连续出现多个同类分型候选：

- 连续多个顶分型，只保留最高的那个
- 连续多个底分型，只保留最低的那个

“最高”按分型中心 K 线的 `high` 比较，“最低”按分型中心 K 线的 `low` 比较。

## 5. 笔定义

### 5.1 笔的构成

一笔由相邻且类型相反的两个有效分型构成：

- 顶分型到后续底分型，形成向下一笔
- 底分型到后续顶分型，形成向上一笔

### 5.2 成笔条件

第一阶段采用较稳妥的“分型确认 + 最小间隔”规则：

- 起点和终点必须是类型相反的两个有效分型
- 顶分型与底分型在包含处理后的三 K 窗口不能共用 K 线
- 在满足“不共用 K 线”的前提下，顶分型中最高 K 线与底分型中最低 K 线之间（不含两端）至少 3 根 K 线
- 上一条“至少 3 根 K 线”按原始 K 线口径统计（不考虑包含关系，不按去包含后的标准化 K 线数量统计）
- 未提供 `normalized_bars` 明细时，当前实现按中心索引做保守近似，要求两分型中心索引至少相差 4
- 笔内不能被更新的更强同类分型替代

严格端点约束：

- 向上笔中，终点顶分型价格必须高于起点底分型价格
- 向下笔中，终点底分型价格必须低于起点顶分型价格

注意：当前实现已经不再要求终点必须突破起点分型三 K 窗口的最高/最低点。此前更严格的“三 K 窗口极值突破”口径已被移除，文档与代码均应以当前价格越界口径为准。

更具体地说：

- 若底分型之后先出现顶分型，则先形成候选向上一笔
- 若在该候选笔确认前又出现更高的顶分型，则用更高顶分型替代旧终点
- 若顶分型之后先出现底分型，则先形成候选向下一笔
- 若在该候选笔确认前又出现更低的底分型，则用更低底分型替代旧终点

### 5.3 笔的确认

当一个候选笔的终点分型已经成立，并且其后出现了满足当前确认口径的反向分型候选时，前一笔被确认。

换句话说，笔允许在末端随行情延伸被更新，但一旦后续反向结构按当前模式形成确认，上一笔即冻结。

### 5.4 笔的属性

每一笔至少输出：

- `direction`: `up` 或 `down`
- `start_fx_id`
- `end_fx_id`
- `start_ts`
- `end_ts`
- `high`
- `low`
- 覆盖的标准化 K 线区间

对于本项目的图表输出与发布 JSON 产物，建议额外保留显式端点价格字段：

- `start_price` / `end_price`：用于前端直接绘制笔的起止价格，避免仅依赖 `high/low` 造成相邻笔看起来断开
- `start_fx_type` / `end_fx_type`：记录端点分型类型，便于回溯和解释

这类字段应从对应分型价格派生，不应把 `high/low` 当成笔线绘制的唯一端点语义。

### 5.5 笔确认口径（本项目当前实现）

为了避免“伪反向笔”，本项目当前把“反向分型能否占住 pending_reverse”单独做成了可切换口径。三种模式共享同一套起笔和延伸流程：

- 笔的识别顺序从左到右，起点分型先形成“候选笔”
- 候选向下笔：从顶分型向后找底分型，且必须满足“分型窗口不重叠 + 极值 K 线之间至少 3 根 K 线”
- 候选向上笔：从底分型向后找顶分型，且必须满足“分型窗口不重叠 + 极值 K 线之间至少 3 根 K 线”
- 候选向下笔的终点底分型价格，必须低于起点顶分型价格
- 候选向上笔的终点顶分型价格，必须高于起点底分型价格
- 若候选笔未被后续有效反向笔确认，则该笔继续延伸（同向更极值分型替代终点）

三种 `pending_reverse_mode` 的差异在于“有效反向确认规则”：

- `any`：当前默认口径。候选笔终点之后首先出现的反向分型即可进入 `pending_reverse`；若其间隔不足，不能立即确认上一笔，但它会持续占位，除非后续出现同类且更强的反向分型替代它。
- `effective_only`：全局结构优先口径。间隔不足的反向分型不会进入 `pending_reverse`，只有本身满足最小间隔的反向分型才有资格参与前笔确认。
- `tail_mixed`：尾部折中口径。先按 `any` 跑完整段历史；若最后一笔仍未确认，则从这根未确认尾笔的起点开始，用 `effective_only` 仅重算最后这段确认链，已确认历史前缀保持不动。

当前批量结构图和技术报告已经支持三种模式；若目标是“尽量保住历史结构，只修正最后一段明显不顺眼的尾笔链”，优先使用 `tail_mixed`。

分型确认依赖笔确认：

- 只有作为“已确认笔”端点出现的分型，才视为确认分型
- 因此分型与笔存在联动确认关系，不应把全部三K分型都直接当成有效分型

### 5.6 笔识别完成项与剩余边界

当前笔实现的“已补齐项”如下：

- 已补齐：在“首个反向分型不满足端点价格约束”时，算法不会提前放弃起点，而是继续向后寻找满足约束的合法反向终点（避免漏识别后续可成笔结构）。
- 已补齐：起笔跳过逻辑已覆盖左边界头噪声与“首笔长期不能确认”两类高频工程场景，并有回归测试约束。
- 已补齐：`any` / `effective_only` / `tail_mixed` 三种 pending-reverse 口径均已接入主流程、图表与测试。

当前仍明确保留的边界如下：

- 保留边界：`tail_mixed` 仍只重算最后未确认尾笔起点之后的确认链，不会回溯重切更早历史。
- 保留边界：当前确认仍基于分型序列工程映射，尚未引入“同级别走势类型递归分解”的严格理论链路。
- 保留边界：`tail_mixed` 是否升为默认值，仍需更大样本（多市场、多周期）统计验证后再定。

## 6. 线段定义

### 6.1 线段输入

线段基于“已确认的笔”序列计算，不直接从 K 线计算。

### 6.2 基本规则

第一阶段采用简化且工程上稳定的定义：

- 线段由至少 3 笔构成
- 相邻笔方向必须交替
- 一条线段必须由一组具有连续推进特征的笔组成

### 6.3 段内特征

向上线段通常表现为：

- 关键高点不断抬高
- 关键低点整体抬高

向下线段通常表现为：

- 关键低点不断降低
- 关键高点整体降低

### 6.4 线段终结

第一阶段采用“被反向破坏”原则：

- 若当前向上线段的结构高低点推进被后续笔有效破坏，则该线段结束
- 若当前向下线段的结构高低点推进被后续笔有效破坏，则该线段结束

这里的“有效破坏”在第一阶段具体化为：

- 对向上线段，后续向下笔跌破该线段最近一个关键低点
- 对向下线段，后续向上笔突破该线段最近一个关键高点

### 6.5 实现建议

线段是最容易出现流派分歧的部分。第一版实现时，建议先保持如下策略：

- 先实现一个可运行的简化版本
- 所有线段拐点都保留中间推导数据
- 用样例图手工比对后再继续迭代

### 6.6 当前实现口径

当前项目中的 `src/chanlun/segment.py` 采用的是“工程化简化线段”规则，具体约束如下：

如需一份更适合人工核图的短说明，见 [segment-implementation-guide.md](segment-implementation-guide.md)。

- 线段识别函数可接收全量笔序列，但实现内部只使用 `is_confirmed=True` 的已确认笔
- 任意未确认尾笔都不参与线段起段、扩展或终结判定
- 起段需要连续 3 笔，且方向必须交替，首尾笔同向，并且前三笔必须存在公共重叠区间
- 起点锚定支持 `auto` / `prefer_earlier_start` / `first_valid_seed` / `skip_left_edge`：默认采用 `prefer_earlier_start`，在接近 `auto` 最优质量的候选里优先更靠左的起点
- `strict_segment_rules` 默认开启：会额外要求“前三笔同向推进”，并把同向相邻线段合并为同一段；如需兼容旧口径可显式关闭
- 反向特征序列在判分型前，会先做同序列内部的非包含处理，得到标准特征序列
- 向上线段起段要求第 3 笔高点高于第 1 笔高点；向下线段起段要求第 3 笔低点低于第 1 笔低点
- 若反向特征序列已经形成无缺口的直接顶/底分型，则旧线段优先在该分型对应极值处终结
- 若反向特征序列分型的第一、第二元素之间存在缺口，则先记录待确认转折点；再按 71 课再分辨思路，比较后续序列是先破这第一笔终点还是先破其起点，从而确认旧线段终结或继续延续
- 段内扩展按“两笔一组”推进：先出现一笔反向回撤，再出现一笔同向创新高/新低，才允许线段继续延伸
- 线段终结先看首根反向笔是否无缺口回补到前一同向极值：若是，则旧段立即终结；若否，则需等待后续同向反抽是否恢复原趋势，只有反抽失败并再次向反方向扩张时，才确认旧段被破坏，且首根破坏笔归入新线段
- 若尾部没有出现有效破坏，但已经满足起段与推进条件，则保留一个 `is_confirmed=False` 的未确认尾段
- `segments.csv` 会额外导出 `last_same_extreme`、`last_reverse_extreme`、`break_bi_id`、`stop_reason`，用于解释该线段最后停在哪一笔、是被反向破坏确认，还是因为尾部未完成推进而停住

这一口径是当前图表导出的实际行为，应视为当前实现标准；若后续要向更严格缠论段定义收敛，应在此基础上单独升级，而不是让文档与代码继续分叉。

### 6.8 双模式口径与中枢传递约束

从当前版本起，线段识别应明确区分 `termination_mode=theory/practical` 两条消费口径，并保持以下规则：

- `theory`：仅 `theory_confirmed` 视为终结；`fallback_confirmed` 与 `pending` 都不应直接终结。
- `practical`：`theory_confirmed` 与 `fallback_confirmed` 都可视为终结；`pending` 仍不可终结。
- 任一模式下出现 `pending`，都只能视为待确认状态，不得在下游中枢层当作完成结构。

当中枢层消费线段结果时，禁止在下游重新发明 stop 分类规则；应复用线段层契约字段并按模式解释。

## 7. 中枢定义

### 7.1 中枢输入

严格定义中，中枢应基于“某级别走势类型”识别。

第一阶段为了工程实现，暂以“已确认笔”作为次级别走势类型的近似代理。

因此本节需要区分两层口径：

- 严格口径：依据缠论原文思想，先区分进入段、中枢内部三段、离开段
- 工程近似：在暂不实现完整走势类型拆分前，用已确认笔近似表达次级别走势类型

### 7.2 最小中枢

按缠论原文思想，某级别走势中枢由至少 3 个连续次级别走势类型的重叠部分构成。

若下跌走势进入某一震荡区间，则最先向下离开原走势的那一笔，更适合作为“进入笔”看待，而不直接计为中枢内部第 1 笔。

在笔级近似口径下，应按以下严格方式识别最小中枢：

- 先识别一笔进入笔，用于说明走势进入某一潜在中枢区域
- 从进入笔之后的反向回拉笔开始，记为中枢内部第 1 笔
- 此后至少还需要连续 2 笔，方向交替，共形成连续 3 笔
- 这 3 笔的价格区间必须存在公共重叠，才可认定为最小中枢

也就是说，不能简单把“任意连续 3 笔重叠”都直接当作中枢；若首笔只是进入笔，则应从其后的反向笔开始重新计数。

设中枢内部这 3 笔的区间分别为：

- 第 1 笔区间 `[low1, high1]`
- 第 2 笔区间 `[low2, high2]`
- 第 3 笔区间 `[low3, high3]`

则中枢区间定义为：

- `zs_low = max(low1, low2, low3)`
- `zs_high = min(high1, high2, high3)`

若 `zs_low < zs_high`，则认为存在有效重叠中枢。

严格口径下还应满足：

- 这 3 笔必须是进入笔之后的连续 3 笔
- 相邻笔方向必须交替
- 不应把进入笔本身直接计入中枢内部三笔

例如：若一段下跌后先出现一笔反弹、再下探、再反弹，这后面三笔才是中枢内部的候选三笔；前面的下跌笔应视为进入笔。

### 7.3 中枢扩展

若后续笔继续与当前中枢区间发生重叠，则该中枢可以扩展。

扩展时：

- 中枢的参与笔列表增加
- 中枢重叠区间重新计算
- 若新重叠区间消失，则当前中枢终结

扩展时仍应维持“进入笔不计入中枢内部三笔”的原则；扩展针对的是已经成立的中枢本体，而不是回头把进入笔并入中枢。

图形表达上也应同步遵守这一点：

- 中枢矩形不应从进入笔起画
- 中枢矩形的左边界应从中枢内部第 1 笔的起点开始
- 中枢矩形的右边界应延伸到最后一笔仍与该中枢区间发生重叠的内部笔结束处
- 进入笔与离开笔属于中枢上下文，不属于中枢本体矩形面积

### 7.4 中枢属性

每个中枢至少输出：

- `start_bi_id`
- `end_bi_id`
- `zs_low`
- `zs_high`
- `peak_high`
- `peak_low`
- 参与笔列表

### 7.5 当前实现状态

当前项目代码中的中枢识别仍采用简化口径。为避免术语混淆，本规范将其统一命名为“类中枢”（笔级近似中枢）：

- 使用已确认笔作为输入
- 从左到右扫描候选区间
- 以 `entering_bi + 3 笔内部笔` 的窗口启动候选中枢
- 要求进入笔本身与首个中枢区间发生价格重叠
- 中枢区间固定为“内部前三笔”的公共重叠区间
- 后续笔只要仍与该固定区间重叠，就追加到同一中枢本体
- 图上矩形按 `bi_ids[0]` 到 `bi_ids[-1]` 的时间跨度绘制，价格区间使用固定的 `zs_low/zs_high`

这意味着，当前类中枢实现与严格口径至少还有以下差异需要明确区分：

- 当前实现虽然没有把进入笔写进 `bi_ids`，但它额外要求“进入笔必须与中枢区间重叠”；这是一种更窄的工程约束，并非本节严格定义本身的必要条件
- 当前实现在扩展中枢时，不会随着新增内部笔重新计算 `zs_low/zs_high`，而是保持首 3 笔形成时的区间不变
- 当前实现的终结判断仍以“后续出现与进入笔同向且向外突破 `zs_high/zs_low` 的笔”为基础；但在工程层已额外补入一类更保守的谱系回写：若后续紧邻中枢复用该走出笔作为进入笔，且两个中枢区间重新重叠，则会把前一中枢标记为“被更大级别扩展重新吸收”
- 当前图形表达能正确把矩形画在中枢内部笔范围内，但仍属于“固定区间矩形”，不是“随扩展重新收敛区间”的严格画法

因此：

- 文档中的本节定义，代表后续应收敛到的严格规则
- 若当前图表结果与本节不一致，应以本节规则为准，后续再修正实现

### 7.6 中枢标准画法

若目标是“严格中枢定义下的标准图形表达”，建议按以下顺序落图：

1. 先确定进入笔
2. 再确定中枢内部连续 3 笔
3. 用这 3 笔公共重叠区间画出最小中枢矩形
4. 若后续内部笔继续与该中枢保持重叠，则向右扩展中枢时间跨度
5. 若采用严格扩展口径，则应根据扩展后的内部笔集合重新计算中枢区间；若采用工程固定区间口径，则必须在图例或文档中明确说明“区间固定于首 3 笔”
6. 离开笔应单独画为离开动作，不应并入中枢矩形本体

对应到图上，应区分 4 个对象：

- 进入笔：说明走势进入潜在中枢区域
- 中枢本体矩形：只覆盖真正参与中枢本体的内部笔
- 中枢扩展部分：本体右边界随内部重叠延长
- 离开笔：同向离开并突破中枢边界的外出段

如果只在图上画一个矩形，但没有区分进入笔、中枢本体和离开笔，那么即使价格区间画对了，结构语义仍是不完整的。

在后续改实现前，建议先把中枢相关输出口径统一到文档：

### 7.8 双轨口径（主辅关系）

### 7.10 原文定理对照（第17/18/20/29课）

本小节用于把“中枢主口径”与原文核心定理逐条对齐。后续文档和实现若与本小节冲突，以本小节优先。

1. 第17课总纲（走势终完美）

- 任何级别的走势类型终要完成。
- 任何完成走势类型至少包含一个中枢。
- 盘整与趋势都必须放在“完成/未完成”的动态框架里讨论，禁止静态截图式断言。

2. 第18课中枢定理组（生、住、坏）

- 中枢定理一（连接约束）：趋势中连接相邻同级别中枢的，必须是次级别及以下走势类型。
- 中枢定理二（维持约束）：盘整中离开与返回中枢的走势类型，必须是次级别及以下。
- 中枢定理三（破坏条件）：某级别中枢被破坏，当且仅当离开后随后的次级别回抽未重新回到该中枢区间。

3. 第20课中枢扩张与中心定理

- 中枢后续只有两条主线：延伸，或产生新的同级别中枢。
- 趋势中前后同级别中枢不得重叠；若围绕波动区间与前中枢体系重叠，应按更大级别中枢扩张解释。
- 中心定理一（延伸判定）：与中枢方向一致的次级别区间若持续与中枢核心区间重叠，则属于延伸；出现明确离开后需进入“扩张/新趋势”分流判定。
- 中心定理二（同级别中枢关系）：同级别中枢之间可归纳为上涨延续、下跌延续或更大级别中枢形成三类。

4. 第29课背驰-转折定理（三级去向）

- 某级别趋势背驰后，去向只允许三类：
  - 最后一个中枢的级别扩展；
  - 该级别更大级别盘整；
  - 该级别以上级别反趋势。
- 任何“背驰后结论”都必须声明级别，不允许跨级别偷换。

5. 与当前双轨体系的映射约束

- 上述定理默认针对标准中枢（`zhongshus`）生效。
- 类中枢（`lei_zhongshus`）可用于辅助提示，但不得推翻标准中枢的定理结论。
- 当主辅结论冲突时，报告必须按“中枢主、类中枢辅”输出，并标注冲突来源。

6. 文档与实现一致性红线

- 禁止把“尾中枢第一次完成”直接等同于“走势类型已经最终结束”。
- 禁止把“未完成走势中的扩张重写”误写为“前一走势完成后接新盘整”。
- 禁止用指标（MACD/均线）结果改写中枢定理判定；指标仅可作为辅助监控层。

## 8. 走势类型与背驰定义

本节补充的是严格理论定义，用于统一术语、图表表达和后续实现目标。

下面的严格定义代表项目后续应收敛到的统一理论口径；当前代码只实现了其中一部分工程映射，特别是“同级别走势类型分解”目前仍以结构状态摘要为主，而非完整严格分解序列。

其中要特别区分两层含义：

- 严格口径：对应缠论原文层面的走势类型、走势分解、走势终完美、趋势背驰与盘整背驰定义
- 工程口径：当前项目是否已经把这些定义完整自动化，是另一件事

### 8.1 基本术语

- 走势：打开某一级别走势图后看到的价格运动整体
- 走势类型：该级别上的上涨、下跌、盘整三类完成形态
- 趋势：走势类型中的上涨与下跌
- 盘整：走势类型中不属于上涨或下跌趋势的完成形态

这里的“走势”与“走势类型”不能混用：

- 走势是连续展开中的客观过程，既包含已经完成的部分，也包含正在进行的部分
- 走势类型是对某一段完成结构的分类结果

### 8.2 盘整与趋势的严格定义

在任一级别上：

- 某完成的走势类型只包含 1 个该级别走势中枢，称为该级别盘整
- 某完成的走势类型至少包含 2 个依次同向的该级别走势中枢，称为该级别趋势
- 该方向向上时称上涨趋势，向下时称下跌趋势

趋势中的同级别中枢之间必须满足：

- 方向一致
- 彼此依次推进
- 中枢区间之间不存在重叠

因此：

- “只有一个中枢”是盘整与趋势的第一条分界线
- “至少两个同向且彼此不重叠的中枢”是趋势成立的必要条件
- 若只有一个中枢后向外运动，但该走势类型尚未完成，不能提前把它确认为趋势

### 8.3 走势终完美

本项目采用如下严格表述：

- 任何级别的任何走势类型终要完成
- 趋势终要完成
- 盘整也终要完成

“走势终完美”在文档中只表达两层含义：

- 任一走势类型不可能永远处于逻辑上未完成状态
- 一种走势类型完成后，必然转化为其他走势类型的展开

这里不能把“终要完成”误写成“立刻反转”或“马上结束”。
一个走势类型在满足最小结构后仍然可能继续延伸，因此“可完成”和“已完成”不是同一件事。

### 8.4 走势结构分解

本项目采用以下两个基础定理作为严格口径：

- 任何级别的任何走势，都可以分解成同级别上涨、下跌、盘整三种走势类型的连接
- 任何级别的任何走势类型，都至少由 3 段以上次级别走势类型构成

落到工程表达时，应把“走势”和“走势类型连接”分开描述：

- 整个观察窗口内的走势，是若干同级别走势类型的连接
- 单个走势类型内部，又必须能继续分解为不少于 3 段次级别走势类型

因此后续无论做图、做 JSON，还是写解释文本，都不能把一段尚未完成的局部波动直接当成独立走势类型输出。

### 8.5 走势类型延伸

为了避免把延伸误判成完成，本项目先统一以下严格口径：

- 盘整在出现 3 段连续次级别走势类型并形成中枢后，已经具备随时完成的条件
- 但只要围绕该中枢继续延伸且未完成类型转换，仍应视为同一个盘整走势类型的延伸
- 趋势在形成 2 个依次同向的同级别中枢后，也已经具备随时完成的条件
- 但只要新的同向中枢继续生成，仍应视为同一个趋势走势类型的延伸

延伸的识别关键不是“已经走了多久”，而是：

- 盘整是否仍围绕原有结构展开，且未确认转换成趋势或其他盘整连接
- 趋势是否仍在生成新的同向中枢，且未确认转换成盘整或反向趋势

### 8.6 完成、延伸与转化示例

为了避免把“走势类型连接”和“一个走势类型内部延伸”混淆，后续统一使用如下记号：

- 小写 `a`、`b`、`c`：同级别走势类型之间的连接段或离开段，级别低于所讨论的主级别走势类型
- 大写 `A`、`B`、`C`：所讨论主级别上的中枢
- 带 `~` 的记号：表示对已发生部分重新组合后，把它视为一个更高一层含义下的已知局部

#### 8.6.1 标准趋势完成例子

若某级别下跌走势可写成：

```text
a + A + b + B + c
```

并满足：

- `A`、`B` 是同级别中枢
- `B` 相对 `A` 依次同向推进
- `A` 与 `B` 之间没有重叠
- `c` 为最后一个离开段，且该走势整体最终完成

则这是一段标准的该级别下跌趋势。

这里的关键不是字母形式本身，而是：

- 两个同级别中枢已经成立
- 中枢之间满足趋势要求
- 整段结构作为一个完整走势类型已经完成

同理，向上趋势也可以写成同样形式，只是方向相反。

#### 8.6.2 “下跌 + 盘整” 的完成连接

若一段 5 分钟下跌走势已经完成，随后又走出一个 30 分钟盘整走势，那么其语义是：

```text
下跌(完成) + 盘整(完成)
```

这表示：

- 前面的下跌已经是一个完成的走势类型
- 后面的盘整也是另一个完成的走势类型
- 两者是两个已完成走势类型的连接

此时不能再把后面的盘整回写成前面下跌内部的一部分，否则会把“类型连接”误写成“同一走势的延伸”。

#### 8.6.3 最后一个中枢扩展时，不是“下跌 + 盘整”

仍以上面的：

```text
a + A + b + B + c
```

为例。若 `B + c` 没有独立完成后再接出一个新的完成盘整，而是在运行中直接发生中枢扩展，例如把原先按 5 分钟理解的最后一个中枢继续扩成 30 分钟中枢，那么其语义不是：

```text
5分钟下跌 + 30分钟盘整
```

而是：

```text
a~ + A~
```

其中：

- `a~` 表示前面已经能确认的一段已知局部
- `A~` 表示由原 `B + c` 继续扩展出来的新中枢结构

这时更准确的理解是：

- 原下跌走势类型尚未完成
- 只是其最后部分发生了更大级别的中枢扩展
- 因而当前仍处于同一个走势类型内部

后续它还可能继续演化为：

```text
a~ + A~ + b~ + B~ + c~
```

也就是在更大级别语义下，继续完成一个新的下跌走势类型。

因此，“最后一个中枢扩展”和“下跌完成后接一个更大级别盘整”在图上可能相似，但结构语义完全不同：

- 前者是未完成走势类型的延续
- 后者是两个完成走势类型的连接

#### 8.6.4 当下只能确认到哪里，就写到哪里

若当前只走到：

```text
a + A + b
```

则只能确认：

- `A` 已经是一个成立的中枢
- `b` 是离开 `A` 的后续运动
- 该运动是否最终形成与 `A` 同级别的 `B`，还不能提前认定

这时不允许因为主观预期就直接写成：

```text
a + A + b + B + c
```

因为：

- `B` 可能最终和 `A` 同级别，从而形成趋势延伸
- `B` 也可能扩展为比 `A` 更大的中枢
- 甚至 `b` 可能很快结束，使前面结构在更高层语义下被重新组合

因此项目文档、图表和解释文本都必须遵循一个原则：

- 只输出当下已经由结构确认的部分
- 对未完成部分只描述其“正在进行的语义”，不提前给完成标签

#### 8.6.5 对图表展示的直接要求

为了把上面的区别落到图表上，任何级别输出都应至少能看出：

- 最近一个已经完成的走势类型到哪里结束
- 当前未完成走势类型从哪里开始延伸
- 当前这段未完成结构是更像“同一走势类型内部扩展”，还是“前一走势完成后新类型已起步但尚未完成”

若图上只能看到局部波动，而看不出“完成边界”和“未完成边界”，则该图对缠论语义来说仍不合格。

#### 8.6.6 尾中枢扩展时的切分判定

同级别走势类型分解当然应按本级别切分，但“尾中枢完成”与“本级别走势类型已经结束”不能直接画等号。

更准确的理解应是：

- 尾中枢完成，只说明当前走势类型已经具备“可以结束”的条件
- 该位置是否真的是本级别走势类型的最终结束点，还要看右侧新结构会不会把它重新解释为“原走势类型内部的更大级别中枢扩展”

因此本项目在文档口径上统一采用更保守的切分原则：

- 只要右侧结构仍能合理解释为“尾中枢扩展”，就优先视为原走势类型内部延伸，不立即切成“前一走势完成 + 新走势开始”
- 只有当前一走势的完成边界在加入右侧数据后仍然稳定，不再需要把尾中枢回写成更大级别扩展时，才把该位置确认为本级别走势类型的结束点

可按下表理解：

| 场景 | 尾中枢状态 | 右侧结构 | 分解动作 | 语义 |
|---|---|---|---|---|
| 1 | 未完成 | 仍在中枢内或刚离开 | 不切 | 原走势类型当然未结束 |
| 2 | 已完成 | 仅有离开段，后续还不够确认 | 暂不切 | 只具备“可结束”条件，还未形成稳定切点 |
| 3 | 已完成 | 后续被重新吸回，且可解释为更大级别中枢扩展 | 不切 | 仍属原走势类型内部延伸 |
| 4 | 已完成 | 后续形成独立的新盘整或新趋势起点，且不需要回写前结构 | 可切 | 前一走势类型结束，后一走势类型开始 |
| 5 | 已完成 | 后续结构方向相反，但仍可能只是尾部扩展重写 | 暂不切 | 先保守，不抢切 |
| 6 | 已完成 | 后续结构已证明前一尾中枢不会再被扩展吸收 | 可切 | 完成边界稳定 |

换句话说：

- 尾中枢完成，是“走势类型可能结束”的必要信号之一
- 但它通常不是充分条件
- 真正的切点，不应机械落在“尾中枢第一次完成”的时刻，而应落在“该完成边界已被右侧新数据证明稳定”的位置

程序化表达时，建议至少区分 3 档状态，而不要只做“已完成 / 未完成”二元判断：

- `ongoing_same_type`：当前仍属同一走势类型内部延伸
- `candidate_completed_waiting_stability`：尾中枢已完成，但仍需等待右侧结构确认该边界是否稳定
- `completed_then_new_type`：前一走势类型结束，后一走势类型已经独立起步

在没有足够信息证明“右侧结构已经独立成立”之前，宁可晚切，也不要因为尾中枢刚完成就过早切成两个走势类型。否则很容易把“最后一个中枢扩展”的场景误写成“前一走势完成后接新盘整”，从而偏离本节 8.6.3 的严格语义。

### 8.7 趋势背驰的严格定义

本节中的“背驰”若不特别说明，默认指趋势背驰，而不是盘整背驰。

严格口径下：

- 没有趋势，没有背驰
- 趋势背驰发生在两个相邻同向趋势段的力度比较中
- 更常见也更标准的情况，是至少第二个同级别中枢之后的离开段，与前一同向离开段比较力度

用 A、B、C 三段表示时：

- A 与 C 为同向运动段
- B 为中间的连接结构，并对应一个把力度指标拉回的中间中枢或中间整理
- 若 C 段创新高或创新低，但力度弱于 A 段，则构成趋势背驰

本项目当前只先固定理论判断边界，不在本节规定唯一的程序化力度公式。可接受的辅助比较方式包括：

- 中枢语义下的结构力度比较
- 同级别 MACD 柱面积或伸长高度的辅助比较
- 均线面积等其他后续明确收敛的力度代理

但无论采用哪种代理，都必须满足：

- 比较对象是同级别、同方向的两个趋势段
- 后段在价格上创新高或创新低
- 后段力度弱于前段

### 8.8 盘整背驰的严格定义

盘整背驰不是“趋势中的标准背驰”，而是盘整语义下的一种类背驰判断。

本项目先统一以下严格口径：

- 若某级别走势尚处于第 1 个同级别中枢附近
- 某次离开中枢的运动试图脱离该中枢，但力度不足
- 随后又被拉回该中枢
- 则这种比较应归为盘整背驰，而不应归为趋势背驰

更具体地说：

- 盘整背驰常用三段结构 A、B、C 来比较第一段与第三段力度
- 这里 A 与 C 不要求都已经构成严格趋势
- 两个盘整段之间也可以比较力度
- 若 C 段突破 A 段极限位置，但力度弱于 A 段，则可认定为盘整背驰

因此：

- 第 1 个中枢之后出现的“类背驰”，默认先归入盘整背驰
- 盘整背驰的技术含义，是一次脱离中枢失败的运动
- 盘整背驰并不自动等同于大级别反转，它还可能继续演化为第三类买卖点或新的盘整连接

### 8.9 背驰段与级别收缩

若某级别某段走势构成趋势背驰或盘整背驰，则该段可称为该级别的背驰段。

后续多级别分析若要定位转折区间，应遵循：

- 先在较大级别确认背驰段
- 再到次级别中寻找该背驰段内部更精确的背驰段
- 通过级别逐步收缩，定位更小范围的转折区间

本条先作为理论与展示要求保留，当前版本不强制要求代码完成整套区间套定位。

### 8.10 图表与解释输出要求

任何级别的走势图、结构图、技术面文本或结构化输出，至少都要同时表达两部分：

- 上一个已经完成的同级别走势类型
- 当前正在进行的同级别走势类型

这样做的原因是：

- 只画当前局部，会丢掉走势类型之间的连接关系
- 只画已完成结构，会失去当下正在展开的动态语义
- 缠论分析必须同时保留“已完成的位次”和“正在进行的未完成结构”

工程上建议至少输出以下字段或等价信息：

- `last_completed_trend_type`：上一个已完成走势类型，取值为 `up`、`down`、`range` 之一
- `current_ongoing_trend_type`：当前正在进行的走势类型，若尚未确认完成则必须显式标注为 `ongoing`
- `last_completed_zs_count`：上一个已完成走势类型包含的中枢数量
- `current_structure_status`：当前结构处于延伸、盘整、离开中枢、回抽确认等哪一种状态

### 8.11 当前工程输出边界

本节需要再次明确：当前项目已经能输出“同级别结构状态摘要”，但这不等价于“严格意义上的同级别走势类型分解已经完整实现”。

当前代码里的同级别结构输出，主要基于同级别中枢之间的相对关系做工程归纳：

- 若相邻中枢彼此不重叠，且后者整体高于前者，则归纳为向上推进
- 若相邻中枢彼此不重叠，且后者整体低于前者，则归纳为向下推进
- 若相邻中枢仍有重叠，则归纳为围绕中枢的盘整或盘整延伸

在此基础上，当前实现会给出两类结果：

- 上一个已完成的同级别结构段
- 当前正在进行的同级别结构段

这类输出的主要用途是：

- 在图表和技术面文本中保留“上一段已完成结构”与“当前未完成结构”的连接关系
- 为当前报告、卡片和解释文本提供稳定、可复核的工程语义
- 避免只输出局部波动，而丢失最近结构位次

但必须强调，当前这类输出仍属于工程摘要，而不是严格理论口径下的完整走势类型分解结果。原因包括：

- 当前实现尚未显式输出“整个观察窗口内由哪些已完成走势类型依次连接而成”的完整序列
- 当前实现尚未对“单个走势类型内部至少由 3 段以上次级别走势类型构成”做递归程序化验证
- 当前实现对走势完成、走势延伸、最后一个中枢扩展、完成后新类型连接之间的区分，仍主要依赖中枢关系归纳，而不是完整的严格分解链路

不过，相比前一阶段，当前工程实现已经补入一类明确的“尾中枢扩展重写”自动判定，用于避免过早切分：

- 若前一中枢已经被识别为终结
- 且后一紧邻中枢复用了前一中枢的走出笔作为进入笔
- 且前后两个中枢区间重新发生重叠
- 则工程上会把前一中枢回写为“被更大级别扩展重新吸收”，不再简单按“已终结”直接切成新走势类型

这意味着，当前工程口径已经能够自动覆盖文档 8.6.6 中“已完成，但后续被重新吸回，且可解释为更大级别中枢扩展”的一类典型场景。

进一步地，当前实现不只停留在“前一中枢被紧邻后一中枢吸收”的单步回写，还支持一类有限的链式收敛：

- 若已经存在 `A -> B` 的吸收关系
- 且后续又形成 `B -> C` 的吸收关系
- 并且 `A` 与 `C` 的中枢区间仍保持重叠
- 则工程上允许把 `A` 的最终 `superseded_by_zs_id` 收敛到 `C`

这一点的意义在于：当前输出里的“被谁最终吸收”不一定只停在最近一跳，而会尽量收敛到当前已知的最终吸收者。但这里的收敛仍然严格受限于“区间重叠仍成立”的条件，不能把它理解成任意远距离的事后重写。

但这一自动能力目前仍有明确边界：

- 自动识别首先仍只从“紧邻中枢 + 复用前一走出笔作为进入笔 + 区间重新重叠”开始成立；后续跨多中枢的收敛，只是在这一前提上做有限传播，不是任意直接识别
- 只覆盖“后一中枢复用前一走出笔作为进入笔”的场景，不覆盖更隐含的结构回写
- 只覆盖“两个中枢区间重新重叠”的场景，不覆盖更高层级但区间未直接重叠的推断式吸收
- 它解决的是“不要过早切”的一部分工程问题，仍不等于完整严格的同级别走势类型递归分解

下一阶段若继续扩展，建议先按“远距离重解释规则草案”推进，而不是直接放宽代码判定。当前较稳妥的草案边界应是：

- 只允许跳过极少量中间过渡结构，不能无限跨段回写
- 被跳过的中间结构必须仍属于“围绕原价格带摆动的过渡型结构”，而不是已经稳定成立的新同级别走势类型
- 更早尾中枢与最终吸收者之间，仍需保有可验证的区间关联，至少不能完全脱离原重叠带
- 在这些约束没有先写成反例和测试前，不应贸然把“远距离重解释”直接程序化

因此，当前工程输出更准确的理解应是：

- 它表达的是“同级别结构状态摘要”
- 它用于回答“最近一段已完成结构是什么、当前正在进行的结构更像什么”
- 它不能单独宣称“严格缠论走势类型分解已经自动化完成”

当前测试中已经有一类已知边界可以说明这一点：若前面已经形成两个同向不重叠中枢，后面又出现与最近中枢重新重叠的新中枢，严格语义下它更可能对应“前一走势完成后进入新的盘整”，但当前实现仍可能把这类场景压缩成更粗的工程级 `range` 摘要。出现这类情况时，应优先把输出理解为“工程结构归纳”，而不是“严格理论标签”。

后续若要把该输出提升为严格口径下的“同级别走势类型分解”，至少还需要补齐：

- 基于全量同级别中枢的完整走势类型分解序列
- 对走势完成、延伸、扩展、连接的显式程序化判定
- 对“最后一个中枢扩展”与“前一走势完成后接新走势类型”这类易混场景的回归测试

在这些能力补齐前，图表、JSON、卡片和解释文本中凡出现“上个已完成走势”“当前进行走势”“走势连接”等表达，都应默认理解为工程结构摘要，而不是严格递归分解后的最终理论标签。

尤其要注意一个常见误解：在 `same_type_extension` 场景下，界面上可能同时出现“上个已完成走势：下跌”和“当前进行走势：下跌”，这并不表示程序把两段完全独立的下跌走势硬切成了两次。更准确的含义是：左侧那段下跌结构已经被确认存在，但右侧新数据暂时仍更适合解释为同一类下跌走势内部的延伸或重写，因此展示层会把它标成“前段已确认同型片段”加“当前进行走势”。只有当右侧结构证明边界稳定、可以独立成新走势类型时，才应切换成“上个已完成走势”加“新的当前走势类型”。

### 8.12 背驰后三级去向判定（第29课）

当某级别趋势发生背驰后，后续去向只允许三类，不得发明第四类：

1. 最后一个同级别中枢扩展。
2. 进入该级别更大级别盘整。
3. 进入该级别以上级别反趋势。

判定时必须显式标注级别。例如 `trend_level=5m`、`next_level=30m`，避免跨级别混写。

| 去向 | 最小结构信号 | 语义 |
| --- | --- | --- |
| 最后中枢扩展 | 反向运动仅回到或围绕最后中枢核心，未形成稳定新级别独立结构 | 同一走势类型内部延续 |
| 更大级别盘整 | 新结构在更高一级形成可持续重叠带，且不等价于原中枢短延伸 | 原级别趋势结束后转入盘整 |
| 更高级别反趋势 | 形成反向趋势的必要中枢与离开段条件 | 趋势反转 |

工程输出建议至少补充：

- `post_divergence_route`: `last_zs_extension | higher_level_range | higher_level_reverse_trend`
- `route_level_from`
- `route_level_to`
- `route_confidence_note`

### 8.13 同级别分解唯一性与连接结合律边界（第36/38/39课）

同级别分解原则：

- 在给定级别下，走势类型分解应唯一。
- 允许使用连接结合律做“当下重组”，但重组只能用于提升可读性和操作一致性，不能改变已确认结构事实。

允许重组（满足全部条件）：

- 不破坏已确认中枢与已确认买卖点。
- 不跨越已确认完成边界改写级别结论。
- 重组前后在同级别下保持可逆解释。

禁止重组（任一命中即违规）：

- 为了匹配预期方向而事后改写已确认边界。
- 把高一级结论下压成低一级“伪确认”。
- 让同一时刻出现互斥级别结论且不标注条件差异。

震荡节奏（简化版，来自第39课思想）：

- 围绕同级别中枢震荡时，可对同向片段做 `A_i` 与 `A_{i+2}` 的力度比较。
- 若出现同向不创新高/不创新低或盘整背驰，应触发“节奏切换”提示。
- 该节奏提示仅作为执行纪律，不替代中枢定义与买卖点主判定。

第39课量化阈值（文档口径，便于后续测试固化）：

- 先计算同向片段强度：`strength(A_k) = abs(delta_price_k) * log(1 + bars_k)`。
- 对比 `A_i` 与 `A_{i+2}` 的强度比：`r = strength(A_{i+2}) / max(strength(A_i), eps)`，其中 `eps=1e-9`。
- 默认阈值建议：
  - `r >= 1.10` 且同向创新高/新低：`oscillation_rhythm_state=up_bias`（向该方向偏强）
  - `0.90 <= r < 1.10`：`oscillation_rhythm_state=balanced`
  - `r < 0.90` 或同向未创新高/新低：`oscillation_rhythm_state=down_bias`
  - 若样本不足（不足 3 个同向片段）或分段未稳定：`oscillation_rhythm_state=pending`
- 任一阈值触发都只改变“监视与执行节奏”，不得单独升级为确认买卖点。

  第39课跨市场参数回放建议表（用于后续测试先行，不代表实盘默认参数立即变更）：

  | 市场与级别 | `up_bias` 阈值 | `down_bias` 阈值 | 最小样本建议 | 回放观察重点 |
  | --- | --- | --- | --- | --- |
  | A股 30m | `r >= 1.10` | `r < 0.90` | `>= 120` 段同向片段对 | 观察震荡市误报率与节奏切换滞后 |
  | A股 5m | `r >= 1.12` | `r < 0.88` | `>= 180` 段同向片段对 | 观察高噪声下 false alert |
  | 港股 60m | `r >= 1.08` | `r < 0.92` | `>= 100` 段同向片段对 | 观察跳空与成交时段差异影响 |
  | 港股 15m | `r >= 1.10` | `r < 0.90` | `>= 150` 段同向片段对 | 观察午间断档对节奏判断的扰动 |

  回放统一约束：

  - 每次回放必须同时记录 precision、recall、平均确认延迟（bars）。
  - 任何参数调整都不能改变 3B/3S 首次回抽硬约束。
  - 若提升 recall 的同时 precision 下降超过 8%，默认回退参数。

工程输出建议：

- `same_level_decomposition_mode`: `single_confirmed | dual_interpretation_pending`
- `recomposition_applied`: `true | false`
- `recomposition_reason`
- `oscillation_rhythm_state`: `balanced | up_bias | down_bias | pending`

### 8.14 中枢震荡监视器（第92课）

定义：

- 中枢区间记为 `[A, B]`，其中点记为 `Z`。
- 每个次级震荡区间中点记为 `Z_n`。

监视语义：

- `Z_n > Z`：震荡偏强。
- `Z_n < Z`：震荡偏弱。
- `Z_n` 逼近或越过 `A/B`：进入变盘预警区。

注意：

- `Z_n` 越界不等于立刻确认第三类买卖点；它是高价值预警，而非最终确认。
- 若越界后未形成三类买卖点，常见结果是中枢级别扩展，应回到扩展路径复核。

工程输出建议：

- `zs_monitor_midline = Z`
- `zs_monitor_zn_series`
- `zs_monitor_bias = strong | weak | neutral`
- `zs_monitor_alert = none | pre_breakout | pre_breakdown`

### 8.15 预警触发但未确认买卖点（第29/92课负例模板）

本模板用于约束“有预警，不等于已确认信号”的输出行为。

负例 A（上沿预突破但未确认 3B）：

- 条件：`zs_monitor_alert=pre_breakout`，且离开后首次回试回到 `ZD-ZG` 区间。
- 结论：不得输出 `confirmed_3B`；仅允许输出 `watch_3B_candidate`。
- 建议文本："出现上沿预突破预警，但首次回试已回到中枢，三买未确认。"

负例 B（下沿预破位但未确认 3S）：

- 条件：`zs_monitor_alert=pre_breakdown`，且离开后首次回抽回到 `ZD-ZG` 区间。
- 结论：不得输出 `confirmed_3S`；仅允许输出 `watch_3S_candidate`。
- 建议文本："出现下沿预破位预警，但首次回抽已回到中枢，三卖未确认。"

负例 C（背驰去向偏反趋势，但级别未闭合）：

- 条件：`post_divergence_route=higher_level_reverse_trend`，但更高级别中枢尚未形成稳定离开-回抽闭环。
- 结论：不得输出“已确认反转趋势”；只能输出“高风险观察，待级别闭合确认”。

统一红线：

- 预警类字段（`zs_monitor_*`）只能触发风险升级，不能替代买卖点确认链。
- `dual_interpretation_pending` 状态下，所有买卖点结论都必须保持 pending/watch，不得升格 confirmed。

## 9. 买卖点口径

买卖点在第一阶段不做完整自动化定义，只做接口预留。

先统一原则：

- 买卖点必须依附于结构，且主口径依附标准中枢
- 不能脱离结构仅根据单根 K 线给出信号
- 结果必须能回溯到触发结构

主辅规则补充：

- 一二三类买卖点的主判定基于 `zhongshus`。
- `lei_zhongshus` 可提供辅助提示，但不得单独触发“确认买卖点”。
- 若主辅冲突，默认保留“中枢优先、类中枢降级为观察提示”。

### 9.1 三类买卖点与中枢关系表（第21/53课）

| 类型 | 与最近中枢的位置关系 | 结构语义 | 级别约束 | 工程输出要求 |
| --- | --- | --- | --- | --- |
| 一类买点（1B） | 通常在最近中枢下方，对应下跌结构转折区 | 由背驰触发的转折起点 | 必须声明所属级别 | 输出 `source_zhongshu_id` 与 `trigger_segment_ids` |
| 二类买点（2B） | 可在中枢下/中/上任一位置 | 对一类买点后的次级别回试确认，属于补位买点 | 同级别判定，不得跨级别偷换 | 输出 `parent_first_type_id` 与 `pullback_segment_ids` |
| 三类买点（3B） | 在中枢上方（向上离开后首次回试不回中枢） | 中枢结束后的延续确认或新趋势确认入口 | 仅第一次回试有效 | 输出 `breakout_segment_id`、`retest_segment_id`、`is_first_retest=true` |
| 一类卖点（1S） | 通常在最近中枢上方，对应上涨结构转折区 | 由背驰触发的转折起点 | 必须声明所属级别 | 输出 `source_zhongshu_id` 与 `trigger_segment_ids` |
| 二类卖点（2S） | 可在中枢上/中/下任一位置 | 对一类卖点后的次级别回抽确认，属于补位卖点 | 同级别判定，不得跨级别偷换 | 输出 `parent_first_type_id` 与 `pullback_segment_ids` |
| 三类卖点（3S） | 在中枢下方（向下离开后首次回抽不回中枢） | 中枢结束后的延续确认或新趋势确认入口 | 仅第一次回抽有效 | 输出 `breakout_segment_id`、`retest_segment_id`、`is_first_retest=true` |

补充约束：

- 所有买卖点都必须绑定“最近中枢关系”，禁止脱离中枢孤立定义。
- 所有买卖点都必须带级别标签，例如 `signal_level=30m`，禁止只给方向不给级别。
- 2B/2S 的主要价值是补足“小级别转大级别”场景；当同级别 1B/1S 不存在时，可作为该级别最佳执行点。

### 9.2 重合与互斥规则（第21课）

- 1B 与 2B 不重合：二类买点定义上依赖一类买点后的次级别回试，时序上必然后置。
- 1B 与 3B 不重合：一类买点在中枢下，三类买点在中枢上，位置语义互斥。
- 2B 与 3B 可重合：当一类买点后出现强离开并首次回试不回中枢，可在同一点同时满足 2B 与 3B。
- 卖点侧对称：1S/2S 不重合，1S/3S 不重合，2S/3S 可重合。

### 9.3 中枢震荡区的执行边界（第53课）

- 在同级别“二类与三类之间”的中枢震荡区，不产生该级别新的确认买卖点；若参与，只能降级到次级别执行。
- 文档与报告必须明确“观察级别 / 判定级别 / 执行级别”：
  - 观察级别：当前主图跟踪级别；
  - 判定级别：买卖点所属级别；
  - 执行级别：实际下单或提示级别，可低于判定级别但不得高于判定级别。
- 若执行级别低于判定级别，输出中必须显式标记 `execution_is_lower_level=true`，防止误把次级别信号当同级别信号。

### 9.4 主辅路径消费规则

- 一二三类买卖点主结论仅由 `zhongshus` 推导。
- `lei_zhongshus` 只能输出 `auxiliary_signal`，不得直接输出 `confirmed_signal`。
- 当主辅冲突时，必须同时输出：
  - `primary_decision = zhongshu`
  - `auxiliary_conflict = true`
  - `auxiliary_note`（简要说明冲突原因）

### 9.5 第三类买卖点“首次回抽/回试”硬约束（第20/21/53课）

第三类买卖点必须满足“离开后第一次回抽/回试有效”，第二次及之后不得再按同一中枢重复确认 3B/3S。

3B（第三类买点）硬约束：

- 前置：价格向上离开最近中枢，形成有效离开段。
- 触发：首次向下回试不回到该中枢区间（不跌回 `ZD-ZG`）。
- 失效：若首次回试已回到中枢区间，或首次回试完成后再次回试才满足条件，均不得记为该中枢的 3B。

3S（第三类卖点）硬约束：

- 前置：价格向下离开最近中枢，形成有效离开段。
- 触发：首次向上回抽不回到该中枢区间（不升回 `ZD-ZG`）。
- 失效：若首次回抽已回到中枢区间，或首次回抽完成后再次回抽才满足条件，均不得记为该中枢的 3S。

工程输出建议增加：

- `third_type_first_retest_only = true`
- `third_type_retest_seq`
- `third_type_retest_valid`
- `third_type_invalidation_reason`

文档红线：

- 不允许用“后续更漂亮的第二次回试”回写第一次失败的 3B/3S。
- 不允许把类中枢侧的首次回试结果覆盖标准中枢侧的首次回试判定。

## 14. 当前版本结论

这份规格代表的是“第一版工程口径”，核心目标是：

- 先统一标准
- 先跑通主链路
- 先让结果可解释
- 再逐步逼近更复杂的缠论流派细节

后续如果要提高精度，应优先通过补测试样例和对比图复盘来修正规则，而不是直接堆更多条件分支。
