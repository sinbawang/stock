# 走势多义性与结合律

本文件定义「走势多义性 + 连接结合律 → 选择最适合当下的中枢/分解」的理论口径（应然）。

它承接：

- [same-level-decomposition-spec.md](same-level-decomposition-spec.md)：同级别分解的理论口径（应然）。
- [trend-type-decomposition.md](trend-type-decomposition.md)：同级别走势类型自动分解主链（TD1，工程唯一分解）。
- [zhongshu-dual-track-spec.md](zhongshu-dual-track-spec.md)：多义性的消费降级 gate。

## 1. 当前定位

- 本文只定义「应然」：多义性下如何用结合律选择分解，以及允许/禁止重组的判据。
- 工程现状（实然）：TD1 主链是**唯一分解**（live run → `range/up/down`），尚未实现「多义性下的当下选择器」。本文是后续工程化的前置理论契约。
- 多义性在 machine-readable 层已由 `same_level_decomposition_mode=single_confirmed|dual_interpretation_pending` 表达，但该 gate 只是「降级器」，不是「选择器」。

## 2. 原文引用（第33/36/38/39/40课）

### 2.1 第36课：结合律与多义性

> 走势类型连接符合结合律，即 A+B+C=(A+B)+C=A+(B+C)，A、B、C 的走势类型级别可以不同。因此，站在多义性的角度……任何一段走势，都可以有很多不同的释义。必须注意，多义性不是含糊性。

> 任何的走势，在结合律上，都可以重新组合，使得走势显示明显的规律性……具体的组合有很多可能，如何根据当下的走势选择一种最有利指导操作的，就是考功夫的事情。

> 组合的一个要点在于，尽量避繁就简，因为中枢扩展比较复杂，如果有组合使得不出现扩展，当然就采取该种组合更有意义。

> 当下采取什么组合，就要按该种组合的具体图形意义来判断、操作。

### 2.2 第38课：同级别分解唯一性

> 根据结合律，如何选择一种恰当的走势分解，对把握当下的走势极为关键。显然，一个好的分解，其分解规则下，必须保证分解的唯一性……其中，最简单的就是进行同级别分解。同级别分解具有唯一性，不存在任何含糊乱分解的可能。

> 组合的规则，是为了方便操作以及判断，只要不违反连接的结合律以及分解的唯一性，就是允许的。

### 2.3 第39课：同级别分解再研究（机械节奏）

> 把 a 定义为 A0，则 Ai 与 Ai+2 之间就可以不断地比较力度，用盘整背驰的方法决定买卖点……该中枢可以从30分钟一直扩展到日线、周线甚至年线，但这种操作不管这么多，只理会一点，就是 Ai 与 Ai+2 之间是否盘整背驰。

### 2.4 第33课：走势的多义性

> 所有走势的多义性，都与中枢有关……一般来说，中枢的延伸不能超过5段，也就是一旦出现6段的延伸，加上形成中枢本身那三段，就构成更大级别的中枢了。

> 除了延伸数量、模本精度造成的多义性，还有一种有实质意义的多义性：多种合理释义都符合理论内在逻辑，这种多义性不是负担，而是可以用多角度对走势进行分析。

### 2.5 第40课：同级别分解的多重赋格

> Ai 与 Ai+2 之间的盘整背驰……相应演化出高一级别的中枢。这个现象保证了，在同级别分解下，一个小级别的操作可以按一个自动模式换档成一个高级别的操作。

> 市场的走势，其实就是这样多重赋格……可以有机地统一在多层次的同级别分解操作中。

## 3. 核心原则

1. **多义性 ≠ 含糊性**：所有合法组合都符合同一严格理论；不能「随便分解」。
2. **结合律**：A+B+C=(A+B)+C=A+(B+C)，级别可以不同。
3. **唯一性优先**：好的分解必须保证唯一性；同级别分解是最简单的唯一分解。
4. **允许重组 / 禁止重组**：
   - 允许：不违反结合律与分解唯一性，且更利于操作/判断的组合。
   - 禁止：改写已确认的结构事实（已完成走势类型、已确认买卖点不得被重组掉）；混搭级别导致分解不唯一。
5. **延伸数量限制**：中枢延伸一般不超过 5 段；出现 6 段延伸（含构成中枢本身的三段）即升级为更大级别中枢，用于消除“延伸数量”造成的多义性。

## 4. 通过结合律选择最适合当下的中枢

在多个合法中枢划分中，按以下优先序选择：

1. **避繁就简**：优先选择「不产生不必要类型边界」的组合（能合并为同类延伸就不拆成新类型）。注意：本文是 38/39 课**同级别分解**的工程实现，同级别分解只按中枢区间重叠与否判定（重叠=延伸，不重叠=趋势），**不处理中枢扩张/更高级别中枢**——「扩张」属非同级别分解视角，不在本选择器判定范围内。
2. **利于操作**：优先选择能揭示买卖点意义（尤其三类买卖点）的组合。
3. **级别一致**：同一操作级别内坚持同级别分解，不混搭级别。
4. **当下锁定**：选定一种组合后，按该组合的图形意义判断、操作，不得混用其它组合的结论。

判定「最适合当下中枢」的可复核标准：

- 该划分是否避免了不必要的类型边界拆分；
- 该划分下三类买卖点位置是否更清晰；
- 该划分是否保持同级别唯一性。

## 5. 消费降级映射

| 分解状态 | 字段 | 消费语义 |
| --- | --- | --- |
| 唯一分解 | `same_level_decomposition_mode=single_confirmed` | 可正常消费；但 `single_confirmed` 只代表当前工程口径已收敛，不等于全部理论缺口关闭 |
| 多义待定 | `same_level_decomposition_mode=dual_interpretation_pending` | 统一降级为 pending/watch，不得渲染成确定性方向 |

> 该 gate 是「降级器」不是「选择器」：它表达「分解是否唯一」，并不自动完成「多义性下的中枢选择」。本文第4节的选择规则是未来补「选择器」的理论契约。

## 6. 与当前工程实现的边界

- 已实现：TD1 唯一分解主链（[trend-type-decomposition.md](trend-type-decomposition.md)）、多义性降级 gate（`dual_interpretation_pending`）。
- 已实现（契约锚点）：`_build_decomposition_selector` 输出 `decomposition_selector = {mode, alternatives, selected, selection_reason}`。
  因同级别分解具唯一性（38/39课），`dual_interpretation_pending` 表达「确认待定」（单中枢/候选新类型尚未确认）而非
  「存在多个合法分解」，故 `alternatives` 恒为空、`selected` 恒为 `None`——选择器仅作为 machine-readable 契约锚点保留，
  未来若引入扩张/更高级别分解（非同级别分解视角）再从此挂接多解枚举。回归见 `test_build_structure_state_decomposition_selector_*`。
- 未实现（后续扩展）：中枢扩张/延伸/新生视角下的「多义性选择」——属非同级别分解（更高/更低级别），本程序当前不做。
- 涉及代码锚点：`build_structure_state`、`_split_live_zhongshu_runs`（当前只做唯一切分）。
