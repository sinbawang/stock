# 缠论本地历史仓库与增量分析 Roadmap

## 背景

当前外部分钟线接口通常只能稳定返回有限窗口（常见 600 根左右），会直接限制结构识别深度和中枢上下文连续性。

本路线图目标：

1. 建立本地可持续累积的 K 线仓库，支持 `1200+` 根输入（本地历史充足时）。
2. 默认改为增量抓取，避免每次全量重复拉取。
3. 在数据层稳定后，再推进线段中枢和分级调度，降低上线风险。

## 执行顺序

1. 本地历史仓库（Phase 1）
2. 增量抓取与增量分析（Phase 2）
3. 线段中枢双轨切换（Phase 3）
4. 交易时段分级调度（Phase 4）

## Phase 1: 本地历史仓库

### 目标

- 每个 `market/symbol/timeframe` 持久化一份历史 K 线缓存。
- 写入具备幂等能力（按 `ts` 去重，允许覆盖修正值）。

### 当前落地（已实现）

- 新增本地仓库路径：`data/cache/kline`。
- 新增模块：`src/chanlun/data/local_bar_store.py`，提供：
  - 持久化读写
  - 时间戳去重合并
  - 增量起点推导（带 overlap）
  - 按 bar 数截尾切片
- `scripts/batch_prepare_chanlun_reports.py` 已默认接入本地仓库，分析输入来自“本地合并后窗口切片”。
- `1200+` 根输入能力已具备，但前提是对应 `market/symbol/timeframe` 的本地历史已累计到足够深度；冷启动时仍受外部数据源单次返回上限约束。

### 验收标准

- 冷启动后可持续累积历史。
- 重复运行不产生重复时间戳。
- 同一时间戳远端修正可覆盖本地旧值。

## Phase 2: 增量抓取与增量分析

### 目标

- 默认只抓“最后一根附近 + overlap 回看窗口”。
- 分析输入由“本次远端返回”切换为“本地合并后窗口切片”。

### 当前落地（已实现）

- `scripts/batch_prepare_chanlun_reports.py` 新增参数：
  - `--use-local-store/--no-use-local-store`
  - `--incremental-overlap-bars`
  - `--local-store-root`
- day/60m/30m/15m/5m/1m 全部接入本地仓库合并逻辑。
- `tech.json` 的 `data_fetch.local_store` 记录增量元数据。
- `--use-local-store` 默认为开启，默认执行路径已改为“读取本地末尾 -> 推导 effective_start -> 远端增量抓取 -> 回写合并 -> 截尾分析窗口”。

### 验收标准

- 二次运行抓取耗时明显下降。
- `data_fetch.local_store` 中可见 `effective_start`、`added_rows`、`updated_rows`。
- 指定更大 `--*-bars`（如 1200）时，若本地历史充足可直接产出。

## Phase 3: 线段中枢双轨切换

### 目标

- 将交易决策口径逐步从“笔中枢”切向“线段中枢”。

### 实施策略

- 双轨并行：同一批数据同时输出 `bi` 与 `segment` 口径摘要。
- 差异报告：对 `summary/conclusion/buy_sell_points` 做结构化 diff。
- 达到稳定阈值后切主口径。

### 验收标准

- 连续观察窗口内无异常发散。
- 关键持仓样本差异可解释并可回放。

## Phase 4: 交易时段分级调度

### 目标

- 交易时段内分层执行不同频率的技术刷新。

### 调度规则

- `9:30~12:00`、`13:00~16:10` 仅在交易窗口运行。
- 每 `30` 分钟执行 `30m` 及以下。
- 每 `5` 分钟执行 `5m` 及以下。
- 每 `1` 分钟执行 `1m`。

### 实施要点

- 任务互斥锁（同标的同周期防并发）。
- 超时熔断与降级（1m 失败不阻塞 5m/30m）。
- 分层日志与告警（按周期拆分）。

### 验收标准

- 一周内任务触发稳定，无重复并发执行。
- 单周期失败可重试，不影响其他周期。

## 近期任务清单（两周）

1. 用真实持仓跑 3 天，评估本地合并命中率与耗时变化。
2. 补“增量回放”测试样本（断档、修正、重复时间戳）。
3. 设计双轨口径 diff JSON 输出，准备 Phase 3。
4. 实现交易窗口调度脚本与互斥锁，先 dry-run 再实盘启用。
