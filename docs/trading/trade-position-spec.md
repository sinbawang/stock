# 交易记录与仓位管理模块 Spec

本页定义「交易记录 + 仓位管理」模块的需求、行为、数据契约与验收标准。它只回答
**要做什么、输入输出长什么样、怎样算验收**；具体实现分层与算法推导见
[trade-position-design.md](./trade-position-design.md)，任务拆解见
[trade-position-tasks.md](./trade-position-tasks.md)。

关联文档：
- [../miniapp/miniapp-cloud-publish-schema.md](../miniapp/miniapp-cloud-publish-schema.md)：小程序只读发布包结构（当前价/K 线数据来源）
- [../chanlun/chanlun-rule-spec.md](../chanlun/chanlun-rule-spec.md)：缠论级别/买卖点口径（纪律增强关联项）

## 1. 目标与边界

### 1.1 目标
在 westock 小程序内，按**股票 + 级别**维度记录每一笔交易，并据此完善仓位管理与交易纪律：
1. 录入交易流水，输入尽量简单。
2. 把流水配对聚合成行展示（已了结 / 待卖 / 待买 + 盈亏）。
3. 展示每只股票各级别的仓位情况（数量 / 均成本 / 最长持有天数 / 仓位% + 颜色报警）。

### 1.2 本模块明确要做
- 小程序端录入 / 编辑 / 删除交易流水。
- 配对展示（同级别内按价差最优抵消配对）。
- 各级别仓位聚合（移动加权均成本、FIFO 最长持有天数、仓位百分比）。
- 可编辑的每股票上限配置（总仓位上限、各级别上限、各级别合理持仓天数）。
- 超限 / 超期 / 浮盈浮亏的颜色报警。

### 1.3 本模块明确不做（v1 边界）
- 不做券商自动对接 / 自动抓取持仓。
- 不在 stock Python 容器侧存储或计算交易数据（容器无状态；交易属用户私有数据）。
- 不做多账户 / 子账户体系（以当前微信用户 `_openid` 为唯一归属）。
- 不做历史资金曲线 / 回测收益统计（保留为后续演进）。

## 2. 名词与级别口径

| 级别 | 含义 | 对应系统周期 |
| --- | --- | --- |
| `m1` | 1 分钟 | `1m` |
| `m5` | 5 分钟 | `5m` |
| `m30` | 30 分钟 | `30m` |
| `md` | 日线 | `day` |

- 首版可选级别固定为 `m1 / m5 / m30 / md`。级别集合后续可扩展（`m15/m60/mw`），但 v1 不开放。
- 市场范围：A 股（CN）+ 港股（HK）。

## 3. 功能需求

### 3.1 录入交易流水（输入极简）
录入字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 级别 level | 是 | `m1/m5/m30/md` 单选 |
| 方向 direction | 是 | `买(buy)` / `卖(sell)` |
| 成交时间 tradeTime | 是 | 允许仅填日期；见 3.1.1 默认补时 |
| 价格 price | 是 | 正数，两位小数 |
| 数量 quantity | 是 | 正整数（股）。卖出在列表中显示为负号，但录入为正数 |
| 备注 note | 否 | 可选文本 |
| 录入时间 createdAt | 自动 | 服务端写入时间，用户不可改 |

#### 3.1.1 成交时间默认补时
- 只填日期（如 `10-23` 或 `2026-10-23`）时：
  - **买入**补 `09:30`。
  - **卖出**：A 股补 `15:00`，港股补 `16:00`。
- 只填 `MM-DD` 时按当前年份补全。
- 填写了完整 `日期 时:分` 则原样采用。

#### 3.1.2 录入体验要求
- 价格、数量提供数字键盘。
- 方向、级别一键切换（默认上次所选）。
- 日期默认今天，用户可改。

### 3.2 配对展示交易
把同一股票的流水按**级别分组**，组内做买卖抵消配对，输出配对行供列表展示。

#### 3.2.1 配对规则
1. 按级别分组。
2. 组内按「价差最优」抵消配对：买单按价升序、卖单按价降序贪心两两配对，消耗
   `min(两边剩余数量)`，允许部分成交拆成多行。
3. 配对成功 → 标记 `done`，计算盈亏；仍有净持仓 → `待卖`（净多）/ `待买`（净空）。

#### 3.2.2 盈亏口径
- **毛利**：`盈亏 = (卖价 − 买价) × 配对数量`，不计佣金 / 印花税 / 过户费。

#### 3.2.3 配对行字段与示例
`级别, 数量, buyTime, buyPrice, sellTime, sellPrice, status, 盈亏`

| 级别 | 数量 | buyTime | buyPrice | sellTime | sellPrice | status | 盈亏 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| m30 | 500 | 260811 | 63.5 |  |  | 待卖 |  |
| m5 | 500 |  |  | 261023 | 57.85 | 待买 |  |
| m1 | 500 | 261023 | 53.52 | 261023 | 54.32 | done | 400 |

> 注：示例中 m1 毛利 = `(54.32 − 53.52) × 500 = 400`。

### 3.3 各级别仓位展示
按股票展示各级别仓位，并给出总仓位与颜色报警。

#### 3.3.1 字段
`级别, 数量, avg成本, 最长持有天数, 仓位%`

| 级别 | 数量 | avg 成本 | 最长持有天数 | 仓位 |
| --- | --- | --- | --- | --- |
| m1 | 1000 | 54 | 2d | 20% |
| m5 | 500 | 55 | 10d | 10% |
| m30 | 2000 | 65 | 120d | 40% |
| md | 1000 | 70 | 420d | 20% |

#### 3.3.2 计算口径
- **数量**：该级别净持仓股数 = Σ买 − Σ卖。
- **avg 成本**：同级别未平仓交易的**移动加权平均**（见 design §5）。
- **最长持有天数**：FIFO 口径下**最早仍未平仓那一笔买入**距今的自然日天数。
- **仓位%**：该级别净持仓股数 / `maxTotal`（该股票总仓位上限股数）。
- **总仓位%**：各级别净持仓合计 / `maxTotal`。示例合计 4500 / 5000 = 90%。

#### 3.3.3 颜色报警
- 级别净持仓 > 该级别上限 `perLevel[level]` → 红色告警。
- 总仓位 > `maxTotal` → 红色告警。
- 最长持有天数 > 该级别合理持仓天数 `holdingDaysThreshold[level]` → 橙/红告警。
- avg 成本对比当前价（最近 K 线价）：浮盈红色、浮亏绿色（A 股习惯：红涨绿跌）。

### 3.4 上限与阈值配置
- 每只股票可设置：`maxTotal`（总仓位上限股数）、各级别上限 `perLevel`、各级别合理持仓
  天数 `holdingDaysThreshold`。
- 配置存 CloudBase，可在小程序内编辑。
- 缺省时回退到全局默认值（具体默认值见 design §4.2）。

### 3.5 当前价来源
- 浮盈浮亏对比用的「当前价」= 该股票最近一根 K 线收盘价，优先取最细级别（1m），
  回退日线。复用现有已发布数据（只读）。

## 4. 数据契约（面向小程序 / 云函数）

### 4.1 交易记录 trade
```
{
  "_id": "...",            // CloudBase 自动
  "_openid": "...",        // 归属用户，自动
  "symbol": "300124",
  "market": "CN",          // CN | HK
  "level": "m1",           // m1 | m5 | m30 | md
  "direction": "buy",      // buy | sell
  "tradeTime": "2026-10-23T10:15:00",
  "price": 53.52,
  "quantity": 500,          // 正整数
  "note": "",
  "createdAt": "2026-10-23T10:16:30",
  "updatedAt": "2026-10-23T10:16:30"
}
```

### 4.2 仓位上限 position_limits
```
{
  "_id": "...",
  "_openid": "...",
  "symbol": "300124",
  "market": "CN",
  "maxTotal": 5000,
  "perLevel": { "m1": 1000, "m5": 1000, "m30": 2000, "md": 1000 },
  "holdingDaysThreshold": { "m1": 2, "m5": 10, "m30": 30, "md": 250 },
  "updatedAt": "..."

```

```
{ "level":"m1","quantity":500,"buyTime":"...","buyPrice":53.52,
  "sellTime":"...","sellPrice":54.32,"status":"done","pnl":400 }
// status ∈ done | wait_sell(待卖) | wait_buy(待买)
```

### 4.4 级别仓位 levelPosition（计算产物，前端用）
```

  "positionPct":0.20,"currentPrice":55.1,"floatPnl":1100,
  "overLevelLimit":false,"overHoldingDays":false,"floatPnlSign":"profit" }
```

## 5. 验收标准
1. 可在小程序内对某股票录入、编辑、删除某级别某方向的交易流水；仅填日期时按 3.1.1 自动补时。
2. 配对列表按级别分组，价差最优抵消；done 行毛利计算正确，净多显示待卖、净空显示待买，
   支持部分成交拆行。
3. 仓位列表各级别数量、移动加权均成本、FIFO 最长持有天数、仓位% 计算正确；总仓位%
   与各级别之和一致（示例 90%）。
4. 超级别上限 / 超总上限 / 超合理持仓天数 / 浮盈浮亏 的颜色报警按 3.3.3 正确呈现。
5. 上限配置可在小程序编辑并持久化；未配置时回退全局默认。
6. 全部交易与配置按 `_openid` 隔离，用户之间互不可见。
7. 纯计算逻辑（配对 / 仓位 / 补时 / 校验）有可独立运行的单元测试，覆盖 §3 示例与
   边界（部分成交、净多、净空、超限、超期）。

## 6. 交易纪律增强（建议 / 分阶段）
- **v1**：录入时若将使某级别或总仓位超上限，给出高亮警告（仍允许录入）；仓位列表对
  超期级别高亮。
- **Phase 2（建议）**：买入可选关联「买入依据」（当时买点类型 buy_1/2/3、类一/类二）；
  卖出记录依据（卖点 / 止损 / 止盈）；增加止损价字段，跌破高亮；首页 / 组合页聚合
  「超限 / 超期」提醒。
